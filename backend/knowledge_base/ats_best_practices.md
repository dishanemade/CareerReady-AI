# ATS (Applicant Tracking System) Best Practices

## Formatting Rules That Affect Parsing

- Use standard section headers: "Experience", "Education", "Skills", "Certifications".
  ATS software looks for these exact or near-exact terms to categorize content.
- Avoid placing important text inside tables, text boxes, or headers/footers —
  many ATS parsers skip these entirely.
- Avoid images, icons, or graphics to represent skills or ratings (e.g., star icons for
  skill level) — parsers cannot read these.
- Use standard fonts (Arial, Calibri, Times New Roman) — decorative fonts can break parsing.
- Save resumes as .docx or a text-based PDF (not a scanned image PDF).
- Avoid multi-column layouts — many ATS systems read left-to-right and can scramble
  column content into the wrong order.

## Content Rules That Affect Scoring

- Mirror the exact keywords used in the job description where truthful (e.g., if the
  JD says "React.js" and you know React, write "React.js" instead of just "front-end frameworks").
- Quantify achievements with numbers where possible ("reduced load time by 40%" scores
  better than "improved performance").
- Include both the full term and common abbreviation for key skills, e.g.
  "Search Engine Optimization (SEO)" — this covers ATS systems that search for either form.
- List skills in a dedicated "Skills" section, not just buried in paragraph text —
  many ATS keyword scans prioritize this section.
- Match the seniority language of the job description (e.g., if the JD says "Senior",
  make sure your years of experience are clearly stated).

## Common Resume Mistakes That Hurt ATS Compatibility

- Missing a dedicated skills section entirely.
- Using company-specific jargon/internal tool names instead of industry-standard terms.
- Listing responsibilities without outcomes or impact.
- Inconsistent date formatting across jobs (mixing "Jan 2020" and "01/2020").
- Overly long resumes (more than 2 pages for most roles) diluting keyword density.
